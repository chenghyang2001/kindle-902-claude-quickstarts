# ch01｜customer-support-agent：知識庫檢索加結構化 JSON 回覆的客服聊天

## 這章在講什麼

- 流程是「先檢索、再生成」：後端拿使用者最後一則訊息去知識庫找片段，放進系統提示，再呼叫 Claude 一次。沒有工具迴圈，也沒有串流。
- 核心設計是「回覆契約」：模型每次回一個固定欄位的 JSON，同時帶回答、思考、情緒、建議追問、分類、是否轉真人。一次呼叫做完五件事，前端三個區塊各取所需。
- 強制 JSON 的手法有三層：系統提示寫格式與兩個範例、訊息最後預填一則 assistant 的 `"{"`、程式端用 zod 的 `responseSchema` 驗證。
- 檢索失敗不讓請求失敗：`retrieveContext()` 回 `isRagWorking: false`，提示改成 `No information found for this query.`，再靠「只能用給你的資訊回答」讓模型轉真人。
- 「轉真人」是模型輸出的一個欄位（`redirect_to_agent.should_redirect`），程式只負責發出瀏覽器事件；真正接到客服系統的部分原始碼沒有做。

## 作者做過的實驗／例子

- 系統提示內建兩個完整 JSON 範例：一個不轉真人（`user_mood` 是 `curious`），一個轉真人（`frustrated`，附 `reason`）。
- `app/lib/customer_support_categories.json` 內建 8 個分類：`account`、`billing`、`feature`、`internal`、`legal`、`other`、`technical`、`usage`，每個附 2～9 個關鍵字。
- 預設參數：檢索 `n = 3`、`max_tokens: 1000`、區域 `us-east-1`；模型選單有 `claude-haiku-4-5-20251001`（預設）與 `claude-sonnet-4-6`。
- README 示範用 `npm run dev:left`、`dev:right`、`dev:chat` 切換版面，背後是 `config.ts` 讀兩個 `NEXT_PUBLIC_` 環境變數。

## 教練解說要點

- 先分清楚哪些是 API 功能、哪些是應用程式自己做的：預填 `"{"` 是訊息的寫法，JSON 驗證是 zod，`thinking` 欄位只是一般文字，不是延伸思考。
- 模型看到的和使用者看到的不一樣：`context` 接了最多 3 段，`ragSources` 卻被 `.slice(0, 1)` 剩 1 筆。
- 提示範例裡的分類代號（`account_management`、`technical_support`）不在分類表內，程式也沒檢查；這正是練習要用程式抓出來的落差。
- 演練裡的檢索是關鍵字比對的假知識庫，不是向量檢索；模型是真的，走 `claude -p`，無法預填 `"{"`，改由 `ask_json` 要求只回 JSON。兩者差異要照實講。

## 演練

> 說明：演練類型：導讀＋小模擬（原專案需要 Amazon Bedrock Knowledge Bases、AWS 憑證與 Next.js，這裡不能實跑）。練習視窗工作目錄是 practice/。官方原始碼在 `~/workspace/claude-quickstarts/customer-support-agent`，只讀不改、不安裝它的依賴、不執行它的啟動指令；要看原始碼用 `PYTHONUTF8=1 python qs_source.py <相對路徑> [起始行 結束行]`。自己寫的程式只用 Python 標準庫（不可 pip 安裝任何套件），檔案放 practice/ch01/interactive/，用 `PYTHONUTF8=1 python ch01/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json，或 practice/claude_cli_client.py 的 Anthropic 相容介面（都走 claude -p，不設任何 API 金鑰、不 mock）；每個練習最多呼叫 2 次，整章最多 4 次。

### 練習 1：把回覆契約與分類表抽成一張表（離線導讀）

**目的**：不呼叫模型，直接從原始碼抽出回覆欄位、分類代號與檢索參數，並用程式找出提示範例與分類表的落差。
**送給練習視窗的提示詞**：

```text
寫 ch01/interactive/contract_table.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型）：
0. 開頭 sys.path.insert(0, os.getcwd())，再 from qs_source import read_text, grep。
1. 讀 customer-support-agent/app/api/chat/route.ts，用正規表示式從 responseSchema 區塊（約第 23～45 行）抽出欄位。
   印表：欄位｜型別｜必填或選填。user_mood 另外列出 6 個允許值。
2. 讀 customer-support-agent/app/lib/customer_support_categories.json（json.loads），印表：id｜name｜關鍵字數。
3. 在 route.ts 裡找所有 "matched_categories": [...] 的範例，取出代號，逐一比對是否在第 2 步的 id 清單內。
   印表：範例代號｜是否在分類表內。
4. 用 grep 在 customer-support-agent/app/lib/utils.ts 找 numberOfResults、slice(0, 1)、region，
   在 route.ts 找 max_tokens 與 content: "{"，印出行號與原文。
5. 把欄位表、允許值、分類 id 存成 ch01/interactive/contract.json（給練習 2 用）。
```

**觀察重點**：

- 欄位表是否有 7 個頂層欄位，其中 `matched_categories`、`redirect_to_agent` 是選填、其餘 5 個必填？
- 分類表是否正好 8 個 id？提示範例的 `account_management`、`technical_support` 是否被標成「不在表內」，只有 `billing` 在？
- 檢索參數是否看到「預設取 3 段、來源只留 1 筆」這組數字？

### 練習 2：假知識庫加真模型，產生並驗證結構化回覆

**目的**：用幾十行假知識庫代替 Bedrock，讓真模型照官方格式回 JSON，再用程式驗欄位，並觀察「查不到就轉真人」是否發生。
**送給練習視窗的提示詞**：

```text
寫 ch01/interactive/fake_kb_chat.py（只用標準庫，不可 input()；開頭 sys.path.insert(0, os.getcwd())）：
1. 假環境（要在程式註解與輸出標明是假的）：FAKE_KB 是 6 筆 dict，欄位 fileName、text，
   內容自編一家虛構軟體公司的客服文件（退款規則、更換付款方式、刪除帳號、API 用量上限、登入驗證、資料隱私各一筆，每筆 2～3 句中文）。
2. retrieve(query, n=3)：用字元 bigram 重疊數打分，取分數大於 0 的前 n 筆。
   回傳 context（text 用兩個換行接起來）、is_rag_working（有結果才 True）、rag_sources（只留第 1 筆，仿官方 slice(0, 1)）。
3. 組系統提示（中文，結構仿官方 route.ts）：客服角色、檢索內容（沒有結果時放 No information found for this query.）、
   只能用提供的資訊回答、8 個分類 id（讀練習 1 的 contract.json）、要求回覆只含 JSON：
   thinking、response、user_mood、suggested_questions、debug.context_used、matched_categories、redirect_to_agent.should_redirect 與 reason。
4. 用 practice/llm_agent.py 的 ask_json 呼叫 2 次：
   問題 A「我上個月被重複扣款，可以退款嗎？」；問題 B「明天台北會下雨嗎？」。
5. 用程式驗證每個回覆（不再呼叫模型）：5 個必填欄位都在且型別正確、user_mood 在 6 個允許值內、
   suggested_questions 是字串清單、matched_categories 每個都在 8 個 id 內、should_redirect 是布林。
6. 印表：問題｜檢索到幾段｜context_used｜user_mood｜matched_categories｜should_redirect｜驗證結果。
   把系統提示、模型原始 JSON、驗證結果寫進 ch01/interactive/fake_kb_report.md。
```

**觀察重點**：

- 問題 A 是否檢索到退款那一筆，`context_used` 為 true、`matched_categories` 含 `billing`、`should_redirect` 為 false？
- 問題 B 是否檢索 0 段（或只有不相關片段），模型回 `should_redirect` 為 true 並寫出 `reason`？
- 兩次回覆是否都通過欄位驗證？有沒有出現表外的分類代號？（每次模型輸出可能不同，照實記錄）
