# ch03｜agents：不到三百行的最小代理迴圈

## 這章在講什麼

- 代理的最小形式是一個迴圈：呼叫模型，回覆裡有 `tool_use` 就執行工具、把結果用 `user` 角色放回歷史，再呼叫模型；回覆裡沒有 `tool_use` 就結束。官方把這件事寫在 `agent.py` 的 `_agent_loop`，核心邏輯不到 300 行。
- 一個工具只需要名稱、說明、輸入格式（JSON Schema）與一個 `execute()`。本機工具、MCP 工具、伺服器端工具對模型來說都是工具清單裡的一項，差別只在誰負責執行。
- 工具出錯不該讓程式停下來：`execute_tools` 把例外包成帶 `is_error` 的 `tool_result` 交還模型，讓模型自己決定怎麼補救；多個工具呼叫預設平行執行。
- 歷史管理是代理的另一半：`MessageHistory` 記每輪 token、超過 `context_window_tokens` 就丟掉最舊的一對訊息並留下一句「已截斷」、替最後一則訊息加 prompt caching 標記。
- 這份程式刻意沒有輪數上限、重試、權限控管。README 明說它不是 SDK，而是讓人把這個樣式搬到自己的語言與產品裡。

## 作者做過的實驗／例子

- README 的最小用法：`Agent(name="MyAgent", system=..., tools=[ThinkTool()])`，再 `agent.run("What should I consider when buying a new laptop?")`。
- 示範筆記本 `agent_demo.ipynb`：把計算機 MCP 伺服器（`tools/calculator_mcp.py`，支援 `+ - * / ^ sqrt`）、Brave 搜尋 MCP 與 `ThinkTool` 一起掛上，問「2022 年奧克拉荷馬市人口的平方根」與「一台 Toyota GR86 裝得下幾根香蕉」。
- 同一本筆記本的第 4 節改用伺服器端工具 `web_search`（`max_uses=5`）與 `code_execution`，請模型查東京人口再寫程式算人口密度。
- 預設參數：`ModelConfig` 的 `model="claude-sonnet-5-5"`、`max_tokens=4096`、`context_window_tokens=180000`；每次請求預設帶 `anthropic-beta: code-execution-2025-05-22` 標頭。

## 教練解說要點

- 迴圈的結束條件只有「這一輪沒有 `tool_use`」。程式不看 `stop_reason`，也沒有最大輪數，所以演練時用 `K902_CLI_MAX_CALLS` 當保險。
- `ThinkTool` 的 `execute()` 只回 `Thinking complete!`，什麼事都沒做；它的作用是讓模型把想法寫進訊息歷史。這是「工具不一定要有外部效果」的最好例子。
- 截斷是直接丟掉最舊的對話，不做摘要。這就是為什麼長時間任務要把狀態寫進檔案（第 10 章），不能只靠對話歷史。
- 演練用轉接層取代 `anthropic` 套件：模型是真的，但自訂工具是「用提示詞模擬的工具呼叫」，不是 API 原生的 tool use；伺服器端工具與 MCP 在這裡都不能用，要照實告訴學習者。

## 演練

> 說明：演練類型：實跑（官方 `agents/` 是純 Python，把 `anthropic` 換成轉接層、`mcp` 用空殼頂替後，`agent.py` 不改一行就能由真模型驅動）。練習視窗工作目錄是 practice/。官方原始碼在 `~/workspace/claude-quickstarts/agents`，只讀不改、不安裝它的依賴、不執行它的啟動指令；要看原始碼用 `PYTHONUTF8=1 python qs_source.py <相對路徑> [起始行 結束行]`。自己寫的程式只用 Python 標準庫（不可 pip 安裝任何套件），檔案放 practice/ch03/interactive/，用 `PYTHONUTF8=1 python ch03/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json，或 practice/claude_cli_client.py 的 Anthropic 相容介面（都走 claude -p，不設任何 API 金鑰、不 mock）；每個練習最多呼叫 2 次，整章最多 4 次。

### 練習 1：讓官方 Agent 由真模型驅動，跑完一次工具迴圈

**目的**：不改官方程式，直接匯入 `agents.agent.Agent`，掛上一個自己寫的本機工具，看真模型如何「要求工具 → 拿到結果 → 回答」，並把訊息歷史印出來對照迴圈的每一步。
**送給練習視窗的提示詞**：

```text
寫 ch03/interactive/run_agent.py（只用標準庫，不可 input()）：
1. 開頭把 practice/ 加入 sys.path（Path(__file__).resolve().parents[2]），然後依序：
   import claude_cli_client, qs_source
   claude_cli_client.install()            # 之後 import anthropic 拿到轉接層
   claude_cli_client.install_mcp_stub()   # 本機沒裝 mcp 時用空殼頂替，印出回傳值
   sys.path.insert(0, str(qs_source.root()))
   os.environ.setdefault("K902_CLI_MAX_CALLS", "3")
   from agents.agent import Agent
   from agents.tools.base import Tool
2. 定義 StockTool(Tool)：name="check_stock"，description 寫「查詢倉庫裡某個料號的庫存數量」，
   input_schema 只有一個必填字串欄位 part_no；execute 從固定字典
   {"A-100": 42, "B-200": 0, "C-300": 7} 查，查不到就 raise KeyError(part_no)。
3. 建立 Agent(name="倉管助理", system="你是倉管助理。回答庫存問題前一定要先用 check_stock 查，不可以猜。用繁體中文回答。",
   tools=[StockTool()], mcp_servers=[], verbose=True, client=claude_cli_client.Anthropic())。
4. 執行 agent.run("料號 A-100 還有幾個？夠不夠出貨 40 個？")。
5. 跑完後印一張表：訊息歷史 agent.history.messages 的每一則 → 序號｜role｜各 block 的 type
   （tool_use 要印 name 與 input，tool_result 要印 content 與是否 is_error）。
6. 最後印出 claude_cli_client.calls_made() 與最終回覆文字，並把同樣內容存成 ch03/interactive/run_agent_log.md。
任何例外都要印出完整訊息後以非 0 結束碼離開。
```

**觀察重點**：

- 訊息歷史是不是剛好 4 則：user 問題 → assistant（含 `tool_use`）→ user（`tool_result`，內容 42）→ assistant 文字回覆？
- `calls_made()` 是不是 2？第 1 次回覆裡有 `tool_use` 所以迴圈繼續，第 2 次沒有所以結束。
- 最終回覆有沒有用到工具給的 42，並回答「夠出貨 40 個」？（模型輸出每次可能不同，照實記錄；若第 1 次沒呼叫工具，說明這是提示詞模擬工具呼叫的限制）

### 練習 2：離線實跑工具錯誤處理與歷史截斷

**目的**：不呼叫模型，直接執行官方的 `execute_tools` 與 `MessageHistory`，親眼看到「工具出錯變成 `is_error`」與「超過上限就丟最舊的一對訊息」兩個機制。
**送給練習視窗的提示詞**：

```text
寫 ch03/interactive/offline_parts.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型）：
1. 開頭同練習 1 的匯入準備（install、install_mcp_stub、把官方 repo 根目錄加進 sys.path），然後
   from agents.utils.tool_util import execute_tools
   from agents.utils.history_util import MessageHistory
   from agents.tools.think import ThinkTool
   from agents.tools.base import Tool
2. A 段（工具錯誤處理）：用 types.SimpleNamespace 造 3 個假的工具呼叫（各有 id、name、input）：
   a. name="think"，input={"thought": "先想一下"}            → 正常
   b. name="boom"，input={}，對應一個 execute 會 raise ValueError("壞掉了") 的 Tool 子類別
   c. name="not_exist"，input={}                             → 工具清單裡沒有
   用 asyncio.run(execute_tools(calls, tool_dict)) 執行，印表：tool_use_id｜content｜is_error。
   再用 parallel=False 跑一次，確認結果相同。
3. B 段（歷史截斷）：造一個假 client，它的 messages.count_tokens 直接 raise RuntimeError（逼官方程式走「字數除以 4」的估算）。
   建立 MessageHistory(model="x", system="s" * 400, context_window_tokens=1000, client=假 client)，印出初始 total_tokens。
   用迴圈加入 6 輪對話：每輪先 add_message("user", f"第{i}輪問題")，再 add_message("assistant", f"第{i}輪回答",
   usage=SimpleNamespace(input_tokens=累計值, output_tokens=150))，其中累計值 = 加入前的 total_tokens + 100。
   每輪結束後呼叫 truncate()，印一列：輪次｜訊息則數｜total_tokens｜第一則訊息的文字前 30 字。
4. C 段：印出 format_for_api() 最後一則訊息的 content，確認被加上 cache_control。
5. 把三段輸出存成 ch03/interactive/offline_parts.md。
```

**觀察重點**：

- A 段：`boom` 的內容是不是 `Error executing tool: 壞掉了`、`not_exist` 是不是 `Tool 'not_exist' not found`，兩者都帶 `is_error`，而程式沒有因此中斷？
- B 段：total_tokens 超過 1000 之後，訊息則數是不是不再一路增加，而且第一則變成 `[Earlier history has been truncated.]`？
- C 段：只有最後一則訊息帶 `cache_control`，前面的訊息沒有？這對應「快取斷點放在對話最尾端」的做法。
