# ch05｜browser-use-demo：用元素參照（ref）操作網頁

## 這章在講什麼

- 操作網頁有兩種指向方式：看截圖回像素座標，或先把頁面轉成帶編號的元素樹再用 `ref` 指定。這個專案兩種都留著，但系統提示要求優先用 ref，座標只當備案。
- 工具是「一個自訂工具＋`action` 參數」：`browser` 工具自己寫 `input_schema`，用 23 個 action 涵蓋導覽、點擊、輸入、讀頁面、填表、執行 JavaScript。
- 讀內容與看畫面分開：`read_page` 拿結構與 ref、`get_page_text` 拿全文、截圖只用來確認，不從截圖讀字。
- ref 是頁面內的暫時編號（`ref_N` 對應 `WeakRef`），元素消失就失效；失效時工具回錯誤，由模型重新 `read_page`。
- 代理迴圈很單純：回應裡有 `tool_use` 就執行並把結果接回去，沒有就結束；沒有步數上限。

## 作者做過的實驗／例子

- README 的示範提示詞：到 news.ycombinator.com 列出前 3 則、到 wikipedia.org 找人工智慧資料、到 github.com 搜尋 playwright；並註明直接搜尋 Google 會遇到 CAPTCHA。
- 寫死的參數：瀏覽器視窗 1920x1080；`CoordinateScaler` 假設模型看到 1456x819，座標乘上約 1.3187 換回實際位置。
- 介面只開放 Anthropic 一個供應商，模型清單是三個 Claude 4.5 模型，預設 `claude-sonnet-4-5-20250929`。
- `find` 動作會把元素樹交給另一次模型呼叫來挑 ref，失敗就退回單純的文字比對。

## 教練解說要點

- ref 點擊不是呼叫 DOM 的 click，而是即時向頁面問元素中心點，再用滑鼠點；它省掉的是「模型從截圖估座標」這一步。
- `_click` 同時收到座標與 ref 時用座標，`_hover` 則用 ref，兩者不一致，別當成通則。
- `streamlit.py` 傳了 `only_n_most_recent_images=3`，但 `loop.py` 的裁圖函式沒有被呼叫，截圖其實會一直累積。
- 練習 2 的工具呼叫是轉接層用提示詞模擬的，不是 API 原生 tool use；網頁也是假的，只有模型是真的。

## 演練

### 練習 1：把 browser 工具拆成一張動作表（離線導讀）

**目的**：不啟動瀏覽器，直接從原始碼讀出 23 個動作怎麼分類、座標怎麼換算、裁圖函式為什麼沒作用。
**送給練習視窗的提示詞**：

```text
寫 ch05/interactive/browser_tool_map.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型）：
1. 用 qs_source.read_text 讀 browser-use-demo/browser_use_demo/tools/browser.py，用 ast 找出 BROWSER_TOOL_INPUT_SCHEMA 這個字典（ast.literal_eval），取出 action 的 enum。
2. 印一張表：action｜瀏覽器專屬｜coordinate 說明有點名｜ref 說明有點名。
   瀏覽器專屬＝navigate、read_page、get_page_text、find、form_input、scroll_to、execute_js。
   後兩欄的判斷：該欄位 description 裡有沒有出現用反引號包住的這個 action 名稱。表尾印四個總數。
3. 照 browser-use-demo/browser_use_demo/tools/coordinate_scaling.py 的 scale_coordinates 自己重寫一個純函式（常數 1456、819、1.2 倍門檻、0.05 容許值、上限為視窗減 1），視窗 1920x1080，印出 (728,410)、(100,100)、(1456,819)、(1800,500) 換算後的結果。
4. 照 browser-use-demo/browser_use_demo/loop.py 的 _maybe_filter_to_n_most_recent_images 重寫一份；造一串假訊息，內含 15 個 tool_result、每個裡面放一個 image block，用 images_to_keep=3 跑，印出函式算到的圖片總數與實際刪掉幾張。
5. 用 qs_source.grep 數 loop.py 裡這個函式名稱出現幾次。
6. 把以上輸出存成 ch05/interactive/browser_tool_map.md。
```

**觀察重點**：

- 動作總數是不是 23、瀏覽器專屬 7 個、coordinate 點名 10 個、ref 點名 3 個？
- (728,410) 是否換成 (960,540)、(1456,819) 被壓在 (1919,1079)、(1800,500) 因超過門檻而不變？
- 15 張圖是否算成 0 張、一張都沒刪（函式只數最上層的 image block），而且函式名稱在 loop.py 只出現 1 次（只有定義）？

### 練習 2：假網頁＋真模型，跑一次 ref 工具迴圈

**目的**：用文字版元素樹代替 DOM，看真模型能不能只靠 ref 完成「填表、送出、讀結果」，並記錄每一步工具呼叫。
**送給練習視窗的提示詞**：

```text
寫 ch05/interactive/fake_dom_agent.py（只用標準庫，不可 input()）。假環境：網頁是下面的 FakePage，不是真瀏覽器；模型是真的。
1. FakePage：元素 ref_1 textbox "Search docs"、ref_2 button "Search"、ref_3 link "Pricing"。方法：
   read_page() 回傳每行一個元素，格式 `- textbox "Search docs" [ref=ref_1]`；
   form_input(ref, value) 只接受 textbox；left_click(ref) 點 ref_2 時，若輸入框有值就把頁面換成結果頁（元素改為 ref_4 heading、ref_5 link，舊 ref 全部失效）；
   get_page_text() 回傳目前頁面文字，結果頁含「3 results for <查詢字>」。
   找不到 ref 時丟錯，訊息用 No element found with reference: "<ref>"。
2. 把 read_page、form_input、left_click、get_page_text 定義成四個自訂工具（name、description、input_schema）。
3. 用 claude_cli_client.Anthropic().messages.create 跑工具迴圈，最多呼叫 2 次：
   第 1 次：system 說明「優先用 ref、可在同一次回覆發出多個工具呼叫」，user 訊息附上 read_page() 的輸出與任務「搜尋 claude，回報找到幾筆結果」。
   依序執行回覆裡每個 tool_use，把 tool_result（錯誤時 is_error=True）放進 messages，再呼叫第 2 次取得最後答案。
4. 每步寫一行到 ch05/interactive/trace.jsonl：step、tool、input、result 前 80 字、is_error。
5. 迴圈結束後不呼叫模型，由程式自己對結果頁呼叫 left_click("ref_2")，把得到的錯誤也記進 trace。
6. 最後印：模型呼叫次數、工具呼叫次數、輸入框最後的值、是否到達結果頁。
```

**觀察重點**：

- 模型是否在第 1 次回覆就依序發出 form_input、left_click，全部用 ref 而沒有要求座標？
- 最後答案是否說出 3 筆結果？如果第 1 次沒有呼叫 get_page_text，它有沒有老實說還沒讀到？（每次輸出可能不同，照實記錄）
- 第 5 步的舊 ref 是否得到 No element found 錯誤？這對應原專案「換頁後要重新 read_page」的規定。
