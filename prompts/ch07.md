# ch07｜computer-use-demo：看截圖、回座標，操作 Linux 桌面

## 這章在講什麼

- 桌面操作沒有 DOM 可問：模型只看截圖、回像素座標，工具用 `xdotool` 把座標變成滑鼠鍵盤事件，再截一張圖回去。
- 截圖與座標要成對縮放：螢幕太大就先把截圖縮到 XGA／WXGA／FWXGA，模型回的座標再放大回實體螢幕。
- 「工具版本」是一組設定：哪個 computer 類別、哪個 bash 類別、要不要 beta 標頭，都集中在 `TOOL_GROUPS`，而且要和模型配對。
- 最新的 `computer_toolset_20260801` 把每個動作變成獨立的成員工具，同一回合依序執行、前面失敗後面就不做。
- 供應商會改變迴圈行為：Claude API 開 prompt caching 而不裁舊截圖；Bedrock、Vertex 不開快取，才裁圖。

## 作者做過的實驗／例子

- 預設值：Docker 螢幕 1024x768；Claude API 預設模型 `claude-opus-4-8`，對應工具版本 `computer_use_20251124`；介面「只送最近 N 張圖」預設 3。
- 測試檔的縮放例子：1920x1080 的螢幕，模型座標 (1366, 768) 換成 (1920, 1080)；1920x1200 對應 1280x800；4096x2160 不縮放。
- 動作數隨版本增加：`Action_20241022` 10 個、`Action_20250124` 16 個、加上 `zoom` 共 17 個，toolset 成員也是 17 個。
- README 建議自己實作時用 XGA（1024x768），不靠 API 自動縮圖。

## 教練解說要點

- 座標的座標系是「模型看到的那張截圖」，不是實體螢幕；放大用 `round`，超出螢幕就回 out of bounds 錯誤。
- 裁圖是「湊滿一批才刪」：要刪的張數先減掉除以門檻的餘數，目的是少動到快取。走 Claude API 時這個數字直接被歸零。
- README 說側欄會預設成符合模型的版本，但對照表裡沒有任何模型對應 toolset，要手動選；`computer_use_20250429` 實際用的是 20250124 的類別與旗標。
- 練習 2 的桌面是假的、截圖是文字、工具是轉接層用提示詞模擬的自訂工具；Anthropic 定義的 computer 工具型別在轉接層會被忽略。

## 演練

> 說明：演練類型：導讀＋小模擬（原專案要在 Docker 容器裡跑 X11 桌面與 VNC，這裡不能實跑）。練習視窗工作目錄是 practice/。官方原始碼在 `~/workspace/claude-quickstarts/computer-use-demo`，只讀不改、不安裝它的依賴、不執行它的啟動指令；要看原始碼用 `PYTHONUTF8=1 python qs_source.py <相對路徑> [起始行 結束行]`。自己寫的程式只用 Python 標準庫（不可 pip 安裝任何套件），檔案放 practice/ch07/interactive/，用 `PYTHONUTF8=1 python ch07/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json，或 practice/claude_cli_client.py 的 Anthropic 相容介面（都走 claude -p，不設任何 API 金鑰、不 mock）；每個練習最多呼叫 2 次，整章最多 4 次。

### 練習 1：工具版本表、座標縮放表、裁圖表（離線導讀）

**目的**：把「版本怎麼選、座標怎麼換、舊截圖何時刪」各做成一張表，不呼叫模型。
**送給練習視窗的提示詞**：

```text
寫 ch07/interactive/version_matrix.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型）：
1. 用 qs_source.read_text 讀 computer-use-demo/computer_use_demo/tools/groups.py，用正規表示式取出每個 ToolGroup 的 version、tools、beta_flag，印表：version｜computer 類別｜bash 類別｜beta_flag。
2. 讀 computer-use-demo/computer_use_demo/tools/computer.py，數出 Action_20241022 的動作數、Action_20250124 新增幾個、COMPUTER_TOOLSET_MEMBERS 有幾個成員，各印一行。
3. 照 computer.py 的 scale_coordinates 自己重寫純函式（三個目標 1024x768、1280x800、1366x768，長寬比容許 0.02，目標寬度要小於實體寬度才縮放，放大與縮小都用 round）。
   對實體螢幕 1920x1080、1920x1200、1024x768、4096x2160 印表：實體大小｜模型看到的截圖大小｜模型座標 (683,384) 換成的實體座標。
4. 照 computer-use-demo/computer_use_demo/loop.py 的 _maybe_filter_to_n_most_recent_images 的算式，取 images_to_keep=3、min_removal_threshold=3，對截圖總數 3 到 10 印表：總數｜刪掉｜剩下。
5. 表下註明：provider 是 anthropic 時 only_n_most_recent_images 被設成 0，此表只適用 bedrock、vertex。
6. 全部輸出存成 ch07/interactive/version_matrix.md。
```

**觀察重點**：

- 版本表是否 5 列，只有 toolset 的 beta_flag 是 None，而 `computer_use_20250429` 和 `computer_use_20250124` 用同一個類別與旗標？
- 1920x1080 是否對應 1366x768、(683,384) 換成 (960,540)；1024x768 與 4096x2160 是否都不縮放？
- 裁圖表是否在總數 5 時刪 0 張、6 時刪 3 張、9 時刪 6 張，中間幾列會剩下超過 3 張？

### 練習 2：假桌面＋真模型，跑一次座標工具迴圈

**目的**：用文字版截圖代替畫面，看真模型回的座標經過放大後有沒有點中元件，並實作 toolset 的「依序執行、失敗即停」。
**送給練習視窗的提示詞**：

```text
寫 ch07/interactive/fake_desktop_agent.py（只用標準庫，不可 input()）。假環境：桌面是下面的 FakeDesktop，截圖是文字不是圖片；模型是真的。
1. FakeDesktop：實體螢幕 1920x1080，元件以實體座標定義：名稱輸入框 (400,300)-(1200,360)、Save 按鈕 (1300,300)-(1500,360)、Cancel 按鈕 (1550,300)-(1750,360)。
   screenshot() 回傳文字：第一行寫 screenshot 1366x768，之後每行一個元件與它在 1366x768 畫面上的範圍（實體座標乘 1366/1920 後四捨五入），以及輸入框目前內容與狀態列文字。
2. 定義三個自訂工具，模仿 toolset「一個動作一個工具」：left_click(coordinate)、type(text)、screenshot()。
   left_click：座標超過 1366 或 768 就回錯誤 Coordinates x, y are out of bounds；否則放大回實體座標，判斷點中哪個元件（輸入框＝取得焦點、Save＝輸入框非空時狀態列改成 saved: <內容>）。type 只在輸入框有焦點時生效，否則回錯誤。
3. 用 claude_cli_client.Anthropic().messages.create 跑工具迴圈，最多呼叫 2 次：
   第 1 次：system 說明「座標以截圖的 1366x768 為準、可在同一次回覆發出多個工具呼叫」，user 訊息附 screenshot() 文字與任務「在名稱欄輸入 K902 然後按 Save」。
   依序執行回覆裡的 tool_use；一旦有一個失敗，後面的都不執行，結果填 Not executed: an earlier computer action in this turn failed.（is_error=True）。
   把所有 tool_result 與新的 screenshot() 文字放回 messages，呼叫第 2 次取得回報。
4. 印表並存成 ch07/interactive/desktop_trace.md：step｜工具｜模型座標｜實體座標｜點中元件｜結果。
5. 迴圈後不呼叫模型，由程式自己送一批 [left_click (2000,1500)、type "x"]，把兩筆結果也加進表。
6. 最後印：模型呼叫次數、狀態列文字。
```

**觀察重點**：

- 模型給的座標是否落在 1366x768 內，放大後點中輸入框與 Save？有沒有點偏？
- 狀態列最後是否是 saved: K902？若模型沒先點輸入框就 type，失敗即停有沒有擋下後面的動作？（輸出每次可能不同，照實記錄）
- 第 5 步是否第一筆回 out of bounds、第二筆回 Not executed（原專案的 `NOT_EXECUTED_ERROR`）？
