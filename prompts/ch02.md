# ch02｜financial-data-analyst：讓 Claude 用工具交出圖表資料

## 這章在講什麼

- 工具在這裡是「結構化輸出的出口」：`generate_graph_data` 在伺服器上沒有執行邏輯，模型只是照 `input_schema` 填出圖表資料，程式拿去畫圖。
- 這不是工具迴圈：每個問題只呼叫模型一次，回覆裡取出 `text` 區塊與 `tool_use` 區塊就結束，沒有把 `tool_result` 送回模型。
- `tool_choice` 是 `{ type: "auto" }`，要不要畫圖、畫哪一種由模型決定；系統提示用六種圖的適用情境與三組資料結構範例來引導。
- Schema 只管到一半：`data` 的每一筆是 `additionalProperties: true`，欄位名稱要靠 `config.xAxisKey` 與 `chartConfig` 的鍵對齊，這是最容易出錯的接縫。
- 程式端要補一層轉換：`processToolResponse` 把圓餅圖資料統一成 `segment`／`value`，再依序配上 `hsl(var(--chart-N))`。CSV 等文字檔則是在瀏覽器端直接併進使用者訊息。

## 作者做過的實驗／例子

- 系統提示內建三組資料結構範例：時間序列（`period`、`revenue`，Q1 2024 是 1250000）、多組比較（`category`、`sales`、`costs`）、圓餅（`segment`、`value`，附 `totalLabel`）。
- 工具定義六種 `chartType`：`bar`、`multiBar`、`line`、`pie`、`area`、`stackedArea`；`ChartRenderer.tsx` 的 `switch` 也是這六個，堆疊面積共用面積元件。
- 預設參數：`max_tokens: 4096`、`runtime = "edge"`；模型選單有 `claude-haiku-4-5-20251001` 與 `claude-sonnet-5-5`（預設）。
- README 示範上傳一張圖片，請它用圓餅圖統計畫面裡最常出現的東西。

## 教練解說要點

- 先問「工具結果回給模型了嗎？」沒有。下一輪對話的歷史裡也只有文字，沒有圖表資料。
- 通過 schema 不等於畫得出來：`xAxisKey` 指到不存在的欄位、`chartConfig` 的鍵在 `data` 裡找不到，schema 都不會擋。
- 圓餅範例的 `chartConfig` 鍵是 `equities`、`bonds`，資料鍵卻是 `segment`、`value`；後端先取第一個鍵、取不到才退回 `item.value`。
- 演練走 `claude_cli_client` 轉接層：這是用提示詞模擬的工具呼叫，不是 API 原生的 tool use，要照實講。

## 演練

> 說明：演練類型：導讀＋小模擬（原專案是需要 `npm install` 與瀏覽器的 Next.js 網頁應用，這裡不能實跑）。練習視窗工作目錄是 practice/。官方原始碼在 `~/workspace/claude-quickstarts/financial-data-analyst`，只讀不改、不安裝它的依賴、不執行它的啟動指令；要看原始碼用 `PYTHONUTF8=1 python qs_source.py <相對路徑> [起始行 結束行]`。自己寫的程式只用 Python 標準庫（不可 pip 安裝任何套件），檔案放 practice/ch02/interactive/，用 `PYTHONUTF8=1 python ch02/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json，或 practice/claude_cli_client.py 的 Anthropic 相容介面（都走 claude -p，不設任何 API 金鑰、不 mock）；每個練習最多呼叫 2 次，整章最多 4 次。

### 練習 1：把工具 schema 改寫成 Python，並寫出驗證器（離線導讀）

**目的**：不呼叫模型，把官方工具定義與後端轉換邏輯搬成 Python，用官方三組範例測出圓餅圖的鍵名落差。
**送給練習視窗的提示詞**：

```text
先看原始碼：PYTHONUTF8=1 python qs_source.py financial-data-analyst/app/api/finance/route.ts 27 91
再寫 ch02/interactive/chart_schema.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型；開頭 sys.path.insert(0, os.getcwd())）：
1. TOOL：把 generate_graph_data 的 name、description、input_schema 照原始碼改寫成 Python dict（欄位名逐字一致）。
2. validate_chart(d) 回傳錯誤清單：四個必填頂層欄位、chartType 在 6 個允許值內、config 必有 title 與 description、
   有 trend 時必有 percentage（數字）與 direction（up 或 down）、data 是 dict 清單、chartConfig 每個值必有 label。
3. check_keys(d) 回傳警告清單（schema 管不到的）：config.xAxisKey 是否在每筆 data 裡；chartConfig 的每個鍵是否是 data 的欄位。
4. process_tool_response(d)：仿 route.ts 第 350～397 行。pie 時每筆改成 {segment, value}（取值順序照原始碼），xAxisKey 改成 segment；
   chartConfig 每個鍵加 color = hsl(var(--chart-N))，N 從 1 起。
5. 測試資料：把系統提示裡的三組範例（時間序列、MultiBar、Pie，約第 256～307 行）抄成 Python dict 並補上 chartType，
   再加 2 筆壞資料（chartType 寫 "donut"；trend 少 direction）。
6. 印表：案例｜validate 錯誤數｜check_keys 警告數｜轉換後第一筆 data｜顏色數。
7. 用 grep 確認 types/chart.ts 與 components/ChartRenderer.tsx 的 chartType 是否同樣六種。
```

**觀察重點**：

- 三組官方範例是否都 0 個 validate 錯誤，兩筆壞資料各被抓到 1 個錯誤？
- Pie 範例是否出現 check_keys 警告（`equities`、`bonds` 不在 `data` 欄位裡），但轉換後第一筆仍是 `segment: Equities`、`value: 5500000`？
- 三個檔案的 `chartType` 是否都是同樣六種？

### 練習 2：真模型對假財務 CSV 產生圖表資料

**目的**：讓真模型讀一小份假 CSV、呼叫 `generate_graph_data`，再用練習 1 的驗證器檢查結構並核對數字。
**送給練習視窗的提示詞**：

```text
寫 ch02/interactive/chart_agent.py（只用標準庫，random.seed(902)，不可 input()；開頭 sys.path.insert(0, os.getcwd())，
並把 ch02/interactive 加進 sys.path 以便 import chart_schema）：
1. 假環境（輸出要標明是假資料）：產生 fake_finance.csv，欄位 quarter,product_a,product_b,product_c，
   8 列（2023 Q1～2024 Q4），數值用 random.randint(200, 900)*1000，存到 ch02/interactive/。
2. 用 practice/claude_cli_client.py：client = claude_cli_client.Anthropic()，呼叫 messages.create 共 2 次，
   參數 model="claude-haiku-4-5-20251001"、max_tokens=4096、tools=[chart_schema.TOOL]、
   system 用中文精簡版（財務視覺化專家、六種圖各適合什麼、不要宣告自己在用工具）。
   使用者訊息仿官方 page.tsx："File contents of fake_finance.csv:\n\n<CSV 全文>\n\n<問題>"。
   問題 1「比較三項產品 8 季的營收走勢」；問題 2「2024 Q4 三項產品的營收占比」。
3. 每次回覆：印 stop_reason 與各 block 的 type；找 tool_use 區塊，取 .name 與 .input。沒有就記錄「模型沒有畫圖」，不重試。
4. 對 .input 跑 validate_chart、check_keys、process_tool_response；
   再核對 data 裡三個產品的值是否等於 CSV 對應列（問題 2 核對 2024 Q4）。
5. 仿官方：不送回 tool_result。
6. 印表：問題｜chartType｜data 筆數｜validate 錯誤數｜check_keys 警告數｜數字相符筆數；
   把兩份原始 .input、轉換後結果與 claude_cli_client.calls_made() 寫進 ch02/interactive/chart_report.md。
```

**觀察重點**：

- 兩次的 `stop_reason` 是否都是 `tool_use`？問題 1 是否選 `line`、`multiBar` 或 `stackedArea`，問題 2 是否選 `pie`？
- 問題 1 的 `data` 是否 8 筆、數字與 CSV 相符？問題 2 轉換後是否變成 3 筆 `segment`／`value`？
- 有沒有 check_keys 警告？呼叫次數是否剛好 2 次？（每次模型輸出可能不同，照實記錄）
