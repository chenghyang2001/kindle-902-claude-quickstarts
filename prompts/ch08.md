# ch08｜computer-use-best-practices：把 computer use 的每個細節攤開來看

## 這章在講什麼

- 這是只支援 macOS 的 computer use 參考實作，定位是「拿來讀、拿來改」：模型看到的每個工具名稱、說明、JSON schema 都明確寫在 `computer_use/tools/`。
- 點擊準不準取決於截圖尺寸：API 把圖切成 28×28 的格子，長邊上限 1568 px、格子總數上限 1568；超過會被伺服器再縮一次，座標系就對不上，所以要自己先縮。
- 控制 context 有三層：prompt caching、裁舊截圖（刪圖不刪字）、伺服器端 compaction（整段摘要）。裁圖方式不對會讓快取每回合失效。
- 批次工具 `computer_batch`／`browser_batch` 讓模型一回合送出多個可預測的動作，省延遲也省費用；遇到第一個錯誤就停。
- 安全靠外圍：`bash`／`python` 包在 `sandbox-exec` 裡（只能寫 scratch、禁網路），README 仍要求在用完即丟的虛擬機裡跑。

## 作者做過的實驗／例子

- 入門任務是讓代理開 TextEdit 打 hello world；`image.py` 檔頭註解：截圖沒先縮，16:10 的 MacBook 螢幕會有約 14% 的系統性點擊漂移。
- README 估算：一張截圖約 1,500 個輸入 token，30 回合後圖片歷史約 45k token；快取命中只付約 10% 的輸入價。
- 預設 `image_prune_min=3`、`image_prune_interval=40`、`autocompaction_trigger_tokens=150_000`，讓截圖多的任務先裁圖。

## 教練解說要點

- 兩個座標系要分清楚：模型回傳的是「送出那張圖」的像素，乘上比例才是螢幕座標。縮圖是為了讓模型看到的圖和你以為的一樣。
- 「只留最後 N 張」每回合換掉的圖都不同，請求前綴一直變；interval 策略讓同一批舊圖在一個週期內固定被換掉，前綴才穩定。
- 批次內的座標都以批次之前那張截圖為準，所以批次最後要加 `screenshot`；模型只送單一動作時，迴圈會在工具結果後附上 `BATCH_REMINDER`。
- 明確 schema 不會觸發 computer use 專屬安全分類器；另外 README 說本體一個快取斷點，`loop.py` 實際最多放 3 個，以程式為準。

## 演練

> 說明：演練類型：導讀＋小模擬（原專案只能在 macOS 上用 pyautogui 與 sandbox-exec 操作真實桌面，這裡不能實跑）。練習視窗工作目錄是 practice/。官方原始碼在 `~/workspace/claude-quickstarts/computer-use-best-practices`，只讀不改、不安裝它的依賴、不執行它的啟動指令；要看原始碼用 `PYTHONUTF8=1 python qs_source.py <相對路徑> [起始行 結束行]`。自己寫的程式只用 Python 標準庫（不可 pip 安裝任何套件），檔案放 practice/ch08/interactive/，用 `PYTHONUTF8=1 python ch08/interactive/xxx.py` 執行。需要真實模型時用 practice/llm_agent.py 的 ask／ask_json，或 practice/claude_cli_client.py 的 Anthropic 相容介面（都走 claude -p，不設任何 API 金鑰、不 mock）；每個練習最多呼叫 2 次，整章最多 4 次。

### 練習 1：重算截圖尺寸與舊截圖裁剪（離線）

**目的**：用標準庫重現 `target_image_size` 與兩種裁圖策略，看到哪些解析度會被縮、哪種裁法會打壞快取。
**送給練習視窗的提示詞**：

```text
寫 ch08/interactive/sizing_and_pruning.py（只用標準庫，不可 input()，30 秒內跑完，不呼叫模型）：
1. 用 qs_source 的 grep 從 computer-use-best-practices/constants.py 抓出 px_per_token、max_edge_px、max_tokens、keep_n_most_recent_images、image_prune_min、image_prune_interval 的預設值，連行號印出。
2. 照 computer-use-best-practices/computer_use/image.py 自己重寫 n_tokens_for_px、n_tokens_for_img、target_image_size（先判斷是否已合格；直式先轉橫式；再二分搜尋），不可 import 官方模組。
3. 對 2880x1800、1920x1080、3840x2160、1456x819、1280x720、1080x1920 各算一次，印表：原始尺寸｜送出尺寸｜格子數｜是否縮過｜螢幕/圖片比例（小數 3 位）。
4. 模擬 60 回合、每回合新增 1 張截圖，比較：
   A. simple：只留最後 keep_n_most_recent_images 張。
   B. interval：保留張數 = (總張數 % image_prune_interval) + image_prune_min。
   每回合記下被換成佔位文字的張數，數出 60 回合中這個數字改變幾次（改變一次＝請求前綴變了、快取要重寫）。
5. 用 image_prune_interval=5 再跑一次 B；三組改變次數與尺寸表寫進 ch08/interactive/sizing_report.md。
```

**觀察重點**：

- 2880x1800 是否變成 1389x868（1550 格、比例約 2.073），1920x1080 與 3840x2160 是否都變成 1456x819（1560 格）？
- 1456x819 與 1280x720 是否沒被縮？這和 `browser_viewport` 預設 `(1456, 819)` 有什麼關係？
- 前綴改變次數是否為 simple 50 次、interval(40) 1 次、interval(5) 12 次？

### 練習 2：假桌面上的批次工具（真模型＋假環境）

**目的**：讓真實模型用 `computer_batch` 一次送出多個動作，對照逐步操作要多幾次模型呼叫，並驗證遇錯即停。
**送給練習視窗的提示詞**：

```text
寫 ch08/interactive/batch_desktop.py（只用標準庫，不可 input()）。模型是真的，桌面是假的：用 Python 類別 FakeDesktop 代替螢幕，沒有任何真實滑鼠鍵盤動作。
1. FakeDesktop 是一個表單：姓名框 (200,100)、Email 框 (200,160)、「同意條款」核取方塊 (60,220)、送出按鈕 (200,280)，命中半徑 20。動作：screenshot（回傳文字版畫面：元件名稱、座標、目前值、焦點）、left_click(coordinate)、type(text)。點空白處回錯誤；沒焦點就 type 回錯誤；三項齊全才可送出，否則回錯誤。
2. 定義兩個自訂工具（name、description、input_schema）：computer（action、coordinate、text）與 computer_batch（actions 陣列，每項同 computer）。computer_batch 照官方 batch.py：依序執行、第一個錯誤就停，回傳每步的 "[i:action] 結果" 與 "batch stopped at actions[i] ... (i completed, n skipped)"。
3. 先做不呼叫模型的本機測試：送 5 步批次，第 3 步點空白處，印出回傳文字後重設桌面。
4. 用 practice/claude_cli_client.py 的 Anthropic().messages.create 跑工具迴圈，最多 2 次呼叫：
   第 1 次：system 說明「你在操作文字模擬的桌面；能預測兩步以上就用 computer_batch；批次最後加 screenshot」，user 附上初始 screenshot 文字與任務「填姓名 Test User、Email test@example.com、勾選同意、按送出」。執行回傳的 tool_use；若只送單一 computer 動作，在 tool_result 後附一段提醒文字。
   第 2 次：把 tool_result 放回 messages 再呼叫，讓模型回報結果。
5. 印出並寫進 ch08/interactive/batch_report.md：第 1 次用了哪個工具、批次幾個動作、表單是否送出成功、calls_made()、逐步做法需要幾次呼叫（動作數＋1）；註明這是提示詞模擬的工具呼叫，不是 API 原生 tool use。
```

**觀察重點**：

- 本機測試是否在第 3 步失敗後停止（2 completed, 2 skipped），後面的動作沒被執行？
- 模型是否一次用 `computer_batch` 送出 6 個以上動作並以 `screenshot` 結尾？2 次呼叫對照逐步的 7 次以上，差距寫出來。
- 若模型改用單一動作，提醒文字有沒有附上？（每次輸出可能不同，照實記錄）
